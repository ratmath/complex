Functions

Elementary functions

eze^zez, the trigonometric and the hyperbolic functions of a complex number, enclosed in a rectangle at whatever precision you ask for. These are single-valued. The ones with branch cuts (logarithm, roots, powers, inverses) are on the next page.

Calling them

import { exp, sin, cos, tan, sinh, cosh, tanh, rect } from "@ratmath/complex";

String(exp("1 + i"));        // "1.4686939399 + 2.2873552872i ± 1.7e-21"
String(sin("1 + i"));        // "1.29845758142 + 0.63496391478i ± 8.5e-22"
String(cos("i"));            // "1.54308063482 + 0i ± 8.5e-22": cosh(1), and the imaginary part encloses 0
String(tan("1 + i"));        // "0.27175258532 + 1.08392332734i ± 8.5e-22"

exp("1 + i", 200);           // the second argument is the precision in bits (default 64)
exp("1 + i", { bits: 200 }); // or an options object
sin(rect("1 + i", "1/100")); // an enclosure in, an enclosure of every value out

The result is a Rect. For an exact input its size is about 2−bits2^{-\text{bits}}2−bits relative to the value (the work is done with guard bits and rounded outward at the end). For an input that is itself an enclosure, the size is whatever the input's width forces.

How they are computed

Each one separates into real functions of the real and imaginary parts, which analytic encloses rigorously:

ex+iy=excos⁡y+i exsin⁡y e^{x+iy} = e^x\cos y + i\,e^x\sin y ex+iy=excosy+iexsiny sin⁡(x+iy)=sin⁡xcosh⁡y+icos⁡xsinh⁡ycos⁡(x+iy)=cos⁡xcosh⁡y−isin⁡xsinh⁡y \sin(x+iy) = \sin x\cosh y + i\cos x\sinh y \qquad \cos(x+iy) = \cos x\cosh y - i\sin x\sinh y sin(x+iy)=sinxcoshy+icosxsinhycos(x+iy)=cosxcoshy−isinxsinhy

The hyperbolic functions are the same ones turned a quarter of the way round: sinh⁡z=−isin⁡(iz)\sinh z = -i\sin(iz)sinhz=−isin(iz) and cosh⁡z=cos⁡(iz)\cosh z = \cos(iz)coshz=cos(iz). The tangents are quotients, tan⁡z=sin⁡z/cos⁡z\tan z = \sin z/\cos ztanz=sinz/cosz, and refuse with code pole when the enclosure of the denominator contains 0, which is how you learn that an input rectangle may contain a pole.

Because the real intervals for xxx and yyy are independent, a rectangle is the natural shape here: the enclosure of eze^zez over a rectangle is the product of an interval for exe^xex with intervals for cos⁡y\cos ycosy and sin⁡y\sin ysiny, with no wasted room beyond what a rectangle around a curved image must have.

What "certified" means here

The true value is inside the rectangle returned. Always, not with high probability. That lets the output prove things: if two enclosures do not intersect, the numbers are different; if the enclosure of f(z)f(z)f(z) excludes 0, then fff has no zero at zzz (or anywhere in an input rectangle). It cannot prove equality, since a rectangle that contains 0 says only "possibly zero"; for that see the exact layer in Complex rationals or the equality tests in symbolic.

Quick first, exact after

refined(name, z, { bits }) wraps any function as a Core Refinement: a fast low-precision value at once (.quick), and the certified one when asked (.exact()). An interface can show the quick value while a slider moves and sharpen it when the slider stops.

import { refined } from "@ratmath/complex";

const r = refined("exp", "1 + i", { bits: 300 });
r.quick.value;    // [1.4686939399158851, 2.2873552871788423] as doubles
r.quick.trust;    // "good" ("unsure" when the input is on a branch cut)
r.exact();        // the Rect at 300 bits
